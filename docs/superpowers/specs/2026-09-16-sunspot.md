# Sunspot — Spec

**App name:** Sunspot
**Deployment:** Vercel
**License:** MIT (app code); third-party data has its own terms, see below

## Summary

Web app that shows where the sun currently reaches in Copenhagen: a shadow
overlay computed from OSM building footprints/heights, and highlighted
"sun spots" — benches and green areas that are currently sun-exposed.

## Tech stack

- Next.js (App Router) + TypeScript
- react-leaflet + OSM raster tiles for the map
- suncalc for solar position
- @turf/turf for polygon geometry (footprint offset, convex hull, point-in-polygon)
- Overpass API (OSM) for buildings, benches, parks/green areas
- Open-Meteo API for cloud cover + temperature
- Vitest for unit tests
- Deployed on Vercel

## MVP area

Copenhagen. Hardcoded bounding box / map center for v1; not user-configurable
yet.

## Features

### 1. Shadow layer

- Fetch building polygons in the viewport from Overpass API (OSM).
- Building height, in order of preference:
  1. `height` tag (meters), if present
  2. `building:levels` tag × 3 meters
  3. default assumption: 6 meters
- Compute sun position (azimuth, elevation) for the requested timestamp via
  `suncalc`.
- For each building, project a shadow polygon in the direction opposite the
  sun azimuth, with length = `height / tan(solar_elevation)`.
- Shadow polygon = convex hull of (footprint ∪ footprint offset by the
  projection vector). This is a visual approximation, not 3D raytracing.
- If solar elevation ≤ 0 (sun below horizon), no shadows are computed —
  surface should indicate "dark" / no shadow layer.
- Output: a GeoJSON FeatureCollection, rendered as a map overlay.

### 2. Weather (Open-Meteo)

- Fetch current cloud cover (%) and temperature for the map's location from
  Open-Meteo (no API key needed at non-commercial volume; 10,000 calls/day,
  300,000/month).
- Open-Meteo blends multiple models, including DMI's for Northern/Central
  Europe.
- High cloud cover → light is diffuse → sun/shadow distinction is less
  meaningful. Surface this to the user (e.g. a badge/note) rather than
  hiding the shadow layer outright.

### 3. Sun spots

- Fetch `amenity=bench` points and green areas (parks, grass — e.g.
  `leisure=park`, `landuse=grass`) via Overpass for the viewport.
- Point-in-polygon test against the shadow layer (turf) to classify each
  bench/area as sun-exposed or shaded.
- Sun-exposed benches/areas are visually highlighted on the map.

### 5. Verification

- Run the dev server and visually confirm, for a known place and time in
  Copenhagen, that: shadows point the expected direction, weather data
  loads, and sun-exposed benches/areas are highlighted correctly.

## Known limitations (carry into UI copy / about-page, not just code comments)

- OSM building height coverage in Copenhagen is decent but incomplete —
  many buildings fall back to the 6m default.
- Shadow calculation is a visual approximation (convex hull of offset
  footprint), not a precise physical/3D model. Do not present it as
  precision data.

## Out of scope for v1

- User-selectable location/time (fixed to "now" in Copenhagen)
- Caching/rate-limit handling beyond basic Overpass query etiquette
- Mobile-specific layout
- Commercial licensing path for Open-Meteo
